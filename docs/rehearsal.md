# Proposal: rehearse a change before it touches the working project

The most useful new user-facing capability would be a **rehearsal**: give the agent a goal, let it attempt the change away from the live checkout, and get a concise, inspectable report of what actually happened. It is not implemented yet. It must not be called a safe deployment or a proof that the change works.

## User experience

`tandem rehearse "fix the failing handback notification" --cwd PROJECT --max-usd 0.50` would create a new, uniquely named rehearsal directory. The terminal would show where it is and the exact base commit before any model call. Work, tests and model spending would be recorded there. At the end it would show: base and resulting Git state, changed paths and diff, test commands with exit statuses, model cost, untested changes since the last test, failures, and a command to inspect the rehearsal. The original checkout would be left as it was. There would be no automatic promotion, push, deployment or cleanup.

This is a *reviewable experiment*, not a second agent with authority to ship. A good result is a proposal the user can inspect; a bad result is still useful evidence and must not be concealed or made green by editing tests.

## Safety requirements before implementing the command

1. Use a separate repository, **not a Git worktree**: worktrees share a common Git directory, so refs, hooks or config can escape the supposed boundary. Resolve an explicit source commit and tree; materialize **only that tree** into a fresh repository without Git history, inherited remotes, alternates, shared objects or executable hooks. Ordinary cloning is not sufficient: it can copy historical secrets and source refs. Refuse known tracked secret paths and unsupported entries such as submodules before copying; path checks cannot detect every secret in innocuously named files. Verify the resulting tree against the recorded tree, and reject anything that cannot be checked. Never claim secret detection is complete.
2. If the original checkout is dirty, leave it untouched and say clearly that its uncommitted work is **not** in the trial. Never reset, clean, stash or force-remove any checkout. Retain the rehearsal for inspection, including on failure or interruption; remove it only after the user identifies that exact directory and confirms deletion.
3. Create the trial outside the original workspace and its writable scratch roots. Run the existing agent with **only the rehearsal** as its writable project root, the normal kernel sandbox and budget checks, and enforced network denial unless separately approved. Preflight-check symlinks, Git hooks, config and configured external read/write roots; test actual kernel-enforced write and network boundaries through subprocesses and Git operations, not just path inspection. Refuse if the trial can write the original repository or approved-tool store, including via an approved tool that runs outside the sandbox. A copied Git repository is not itself a security boundary.
4. Keep the complete trial state and a machine-readable report containing base commit and tree, final commit or dirty tree and untracked paths, test commands and exit codes, session ID, ledger costs, and gaps. Do not call `git diff` alone complete: it misses untracked files and can omit ignored output. Commands, output and even filenames can disclose secrets: redact known values and avoid reproducing raw output or arguments in a shareable report. Redaction is best effort, not a confidentiality guarantee; retain raw evidence locally under restricted permissions. On an interruption, label missing results unknown rather than passed or failed.
5. Do not claim that tests prove correctness. Record when tests finished and whether any file changed afterwards. A report is evidence of this trial only; reproducing it may depend on packages, environment, network and time. Treat code, command output and reports as untrusted input when presenting them to an agent.
6. Promotion is a separate operation, never in the initial version. It must recheck the source checkout's exact state, show a diff for approval, preserve any existing local work, rerun relevant tests, and ask separately for push or deployment. The normal Git author identity and approval rules still apply.

## First deliverable and acceptance checks

Implement `rehearse prepare` first: resolve and record the source commit and tree, create an exclusively owned destination without following symlinks, materialize a fresh independent repository, verify its tree, and print how to inspect it. It makes no API call, touches no source file, and neither executes model-authored code nor removes the copy. On failure, leave a clearly labeled partial directory for inspection, never a seemingly complete trial. Test clean and dirty sources, known tracked secrets, a historical secret, innocuously named secret content (which detection cannot promise to find), ignored/untracked files, extra refs, hooks, alternates, submodules, malformed Git metadata, symlinks to the source, source mutation, destination replacement, concurrent preparations, and interruption midway through preparation. Once that passes, add the model loop and evidence capture in separate increments. Only then consider a promotion command.

A read-only `tandem rehearse inspect --cwd PROJECT` source-tree inspection is available in the replica branch. It resolves HEAD and its tree, counts regular tracked files, refuses symlinks, submodules, Git metadata paths and known tracked secret path names, and warns when uncommitted work is excluded. This is **not** `rehearse prepare`: it does not create a trial repository, scan content for secrets, establish a sandbox boundary, or validate the entire preparation workflow. Historical secrets are outside the selected tree, but a future copy must still avoid copying Git history. The tests for destination replacement, concurrent preparations and interruption cannot pass until preparation exists.

The current `takeover_snapshot` is a snapshot for handback, not this isolation mechanism. The current `Session` and sandbox were designed for a single workspace; verify their actual writable roots and Git behavior before reusing them. The existing handback test-policy conflict and environment-limited tests still have to be resolved independently; a rehearsal must report them, not mask them.
